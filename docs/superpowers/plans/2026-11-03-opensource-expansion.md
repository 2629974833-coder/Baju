## Contracts and ownership

1. `backend/extractor.py` (extractor agent) exports `ExtractorService(browser, policy)` and `async extract(site, page_url, *, headers=None, cancelled=lambda:False, max_entries=20, html=None) -> dict`. Result: `{assets: list[asset_record], entries: list[{pageUrl,title,ordinal?}], status: 'resolved'|'unsupported'|'needs-user'|'limited', message: str, extractor: str}`. Normalized records use existing `sourceUrl/pageUrl/title/kind/engine/mime/_headers` fields; DASH remains video engine `yt-dlp`, `_protocol:'dash'` hint or MIME/extension identifies it. Keep internal format/identity information private. No signed URLs in error messages. Only built-in explicitly audited extractors are enabled (start Generic); unsupported delegated providers stay explicit. Not a claim of all upstream sites enabled.
2. All yt-dlp metadata networking goes through a sole custom RequestHandler -> existing policy + HTTP transport + browser cookies, scoped for every redirect. No plugin loading, user config, cache, JS runtime downloads, external extractor commands or unrestricted fallback network. Budgets: <=4 MiB response, <=16 MiB total, <=32 requests, <=30 seconds, <=20 entries, recursion <=3, bounded input JSON POST. Cancellation stops further requests. Rendered HTML may be supplied for the original same-page GET; never send it to another service.
3. `backend/dash.py` and `backend/downloader.py` (DASH agent) use installed yt-dlp `InfoExtractor._parse_mpd_formats_and_subtitles` offline, not a new DASH parser. Support static single-Period MPD, SegmentList/SegmentTemplate/Timeline within pre-expansion limits, one selected video plus audio, initialization segments. Reject DRM/dynamic/SegmentBase/byte ranges/unsafe or excessive expansion. Fetch through existing `_fetch` and use private checkpoints tied to original source, complete manifest and representation identity. Assemble local tracks and restricted FFmpeg copy/mux. Preserve HTTP/HLS behavior. `DownloadAccessRequired(status_code)` typed ValueError for 401/403/402; preserve resumable partials; do not treat 429 as auth failure.
4. `backend/site_adapters.py`, `backend/tasks.py`, `backend/store.py`, recovery/catalog tests (recovery agent). `refresh_identity_matches(old,new)` must bind exact page and media identity; Lustflix binds series slug + episode + media role/path, not just title/classification/duration. Generic unknown identities only allow exact media URL, with refreshed scoped headers/cookies. No broad query stripping. `Scanner.resolve_asset(site, asset, cancelled) -> {status,candidate?,reasonCode,message}` is root-owned scanner hook.
5. Task recovery happens once on `DownloadAccessRequired`: phase refreshing -> resolve exact original page only -> unique matching candidate -> retry once, preserving asset ID/manual classification/tags/originals. Changed URL does not bypass checkpoint validation. Unresolved/ambiguous/gated/repeated auth errors become `needs-user` with sanitized failureCode/recoveryAction; pause/cancel win during resolution. `needs-user` reserves its asset and supports retry/cancel. Explicit retry is a fresh bounded attempt.
6. Catalog helper accepts observed visible links and explicit page count evidence. Persist `scan.catalog` with adapterId, scope, expectedCount (null unless explicitly observed), entries with ordinal/pageUrl/title/access/assetIds, enumerated/resolved/downloaded counts, missing/blocked/truncated reasons. No max-ordinal-as-total inference and no claiming all-site completeness. Manual labels never establish same-episode identity or full-file proof. Root integrates scanner/API/UI and tests; recovery agent supplies helper contracts early.
