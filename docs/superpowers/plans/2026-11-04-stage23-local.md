# 阶段二、三：运行维护与真实媒体处理本地交付

> 执行：分文件所有权并行开发，测试先失败再实现，独立复审和最终全链路验收。不提交、不回滚已有工作区改动。

**目标：** 在本机完成阶段二运行维护及阶段三 CPU 处理/成品版本闭环；用户以后提供服务器做现场验收。

**架构：** 沿用 FastAPI/SQLite/单进程。运行维护模块提供工作区文件锁、磁盘余量保护、worker 心跳、可验证备份和离线恢复；媒体处理使用 Pillow/FFmpeg CPU 引擎及独立持久化 `processingJobs` 队列，原件状态和路径不变，新增成品版本。现有面板接入真实接口，不引入新前端框架。

**技术：** Python 3.12、Pillow、FFmpeg/FFprobe、SQLite backup API、fcntl、原生 JS/CSS。CPU 处理并发为 1、FFmpeg 线程有界；不使用 GPU、超分或未知 AI 修复服务。

## 数据与接口约定

- 处理选项：`{mode:add|remove|both,text,position:top-left|top-right|bottom-left|bottom-right,opacity:0..100,fontSize:1..20,region:{x,y,width,height}}`。字号为画面高百分比，区域所有值均为百分比，去除模式要求区域明确且不越界。
- `POST /api/processes {ids,options}`：仅处理本地已下载原件，按素材和规范参数去重；返回 added/duplicates/blocked。
- `POST /api/processes/{id}/action {action:pause|resume|retry|cancel}`。暂停及服务重启后从原件重新处理，不宣称编码断点续传。
- `state.processingJobs` 独立数组；完成后只追加 `asset.versions`，含 id、参数、时间、SHA256、尺寸、时长、大小、引擎及可访问 fileUrl，私有路径不公开。
- `GET /api/assets/{id}/versions/{versionId}/file`：预览/下载版本，原件接口兼容；成品批量导出按来源、图片/视频类别、素材名整理。
- `GET /api/operations`：数据库、磁盘、依赖、worker 心跳、队列计数、脱敏失败原因；`GET /api/ready` 根据实际准备状态返回 200 或 503，旧 health 存活接口保持。
- `POST /api/maintenance/backups`：无排队/运行工作时，暂时阻止新写入，保存打开会话，生成并验证备份；`GET /api/maintenance/backups` 列元数据，`POST /api/maintenance/backups/{id}/verify` 重新哈希校验。
- `python -m backend.backup create|verify|restore`：与应用共享工作区锁，恢复仅允许新的空目标；拒绝路径越界、符号链接及不完整/篡改备份。在线 API 只使用其持有的工作区锁及静止窗口，不提供任意跳过锁开关。
