# 单条社交视频下载

在总览粘贴作品链接，选择「单集或短视频」，点「直接下载」。解析成功后自动加入下载队列，完成后点「保存到本机」。公开作品无需先登录或导入账号。支持抖音作品与分享短链、YouTube watch / Shorts / youtu.be、TikTok 作品与分享短链、Instagram 帖子 / Reel。一次读取对应作品；主页、合集和播放列表不作为单条视频处理。

单作品请求使用 `POST /api/intake` 的 `autoDownload: true`；未传时仍保持只解析，整站和整部剧不能启用该参数。扫描完成与本次素材入队在同一事务中提交，刷新或切页不会重复入队；只下载本次观察到且属于当前来源、所选类型的素材。取消、失败或解析不完整时不自动下载。容量不足等入队错误会显示在结果里，可处理后手动重试。

抖音分享短链在取得并验证作品地址后直接读取公开移动页，避免为确定作品编号多打开桌面播放器。空元数据、未知业务码和未取得视频不再被当作必须登录；只有明确的权限响应才提示源站访问受限。公开工具不会自动弹出授权窗口，也不共享任何账号。

## 下载与水印

- 使用锁定版本的 yt-dlp 平台解析器，不调用第三方解析站。YouTube 配套安装官方 yt-dlp-ejs 与 Deno；脚本没有网络和文件系统访问权限，扫描取消、截止时间和输出上限都会终止并回收进程。
- 优先取发布方提供的播放文件或明确标注的无水印源。不会在下载时额外加水印。`播放源`只是来源说明，不能证明画面无水印；已经嵌入画面的文字或标志可能仍在。
- YouTube 优先兼容浏览器的 H264 + AAC MP4，支持分离音视频合并和有界 HLS。保存前核对两种轨道与源视频完整时长。没有完整来源时不把静音视频轨或预览当作成片。
- Instagram 的原生描述如提供分离音视频，分别通过受控下载器获取并本地合并。公开嵌入页可能不提供音频信息，不能据此断定原作静音。
- 抖音与 TikTok 在同等水印依据下优先 H264。已声明作品时长时，下载完成后核对时长，明显截短的文件不会替换原件。
- 文件先保存到临时位置，通过媒体检查后发布；保留现有断点续传、有限重试、取消、SHA256、浏览器 Range 播放与单文件导出能力。

源站仍可要求登录、验证或限制服务器出口。失败与等待授权保持为失败状态，不伪装下载成功；不支持 DRM。公开站点不会向访客共享站长账号、Cookie 或其他访客文件。

## 实际验收方法

`scripts/social_acceptance.py` 用临时工作区运行真实 API 的拾取、队列下载和文件导出。对每个成片比较导出 SHA256、检查 Range 206、执行 FFmpeg 全片音视频解码，并保存时间分布截图供目视复核。它不自动判定水印消失，也不把一次公开作品成功外推为全平台成功。

```sh
uv run python scripts/social_acceptance.py --platform all --keep-media --output test-output/social-acceptance
uv run python scripts/social_acceptance.py --platform douyin --url 'https://v.douyin.com/lFT4mm8AhKk/' --auto-download --keep-media --output test-output/anonymous-download
uv run python scripts/social_acceptance.py --platform instagram --url 'https://www.instagram.com/reel/实际作品编号/' --keep-media
uv run pytest tests_backend -q
npm test
npm run check
```

本机网络使用 fake DNS 时，只有已核实该环境的本机验收可加 `--trust-fake-dns`；服务器保持关闭。需要有 FFmpeg / ffprobe。默认真实样本不需要导入账号。验收报告保留失败原因、音轨数量与水印检查范围，生产更新以最后一次候选镜像验收为准。

生产更新保留 `/var/lib/framekeep` 数据卷及公开访客隔离配置；先检查运行中的任务，保留前版镜像再切换候选镜像。更新后检查 HTTPS、`/api/ready`、两名访客的数据隔离与真实文件导出。不要清空访客数据来完成更新。

上游参考：[yt-dlp](https://github.com/yt-dlp/yt-dlp)、[官方 EJS 运行说明](https://github.com/yt-dlp/yt-dlp/wiki/EJS)。

## 2026-11-13 实际候选验收

同一最终容器镜像在目标服务器正常 DNS、匿名访客会话下依次执行，四项本轮均一次通过。每项均包括完整下载、全片严格解码、导出文件哈希一致及 Range 206。

| 平台 | 公开样本 | 实际成片 | 音轨 |
|---|---|---|---|
| 抖音 | 用户提供的 `v.douyin.com/lFT4mm8AhKk/`，作品编号 `7699529763597059450` | 20.567 秒，720×1280，3,817,848 字节 | AAC 双声道 |
| YouTube | `jNQXAC9IVRw` | 19.064 秒，320×240，744,413 字节；实际合并 133+140 两轨 | AAC |
| TikTok | `@scout2015/video/6718335390845095173` | 10.542 秒，576×1024，2,953,029 字节 | AAC |
| Instagram | `BQ0eAlwhDrw` 轮播的第一个视频附件 | 4.004 秒，640×640，39,753 字节 | 官方 `has_audio=false`，原始静音 |

四项都使用 H264。Instagram 这次真实验收覆盖一个官方静音附件；有声双轨的合并、缺轨及截断保护由真实本地音视频文件回归覆盖，尚不是 Instagram 有声作品的线上验收。不能把这些短样本作为长视频、所有作品或全平台可用性的证明。

抖音在较早请求中出现过 `needs-user` 和旧样本 CDN TLS reset；用户样本后续正常访客请求取得播放源，未关闭 TLS 验证、改写 CDN 地址或使用共享账号。其他作品仍可能受源站验证或出口限制。TikTok 的另一个实际样本 `@hankgreen1/video/7047596209028074758` 虽能下载，但可取得的播放版本包含移动水印；播放源标签不等于保证无水印。

历史证据保存在独立的本机验收目录，不随源码发布。复验时应将下载报告、浏览器播放与目视检查记录和对应成片的 SHA256 一并保存；失败诊断单独保留。

### 同日匿名直接下载更新

公开单作品不需要预先授权，主操作为「直接下载」。修复抖音分享短链为识别作品编号多请求桌面页的问题，以及空元数据被误判为需要登录的问题；真实访问限制仍会报告。自动下载由后端在完成扫描的事务中提交。

当次完整后端回归 1,190 项通过，随后公开缓存与隔离回归 32 项通过；239 项前端测试、Ruff 和 JavaScript 语法检查通过。这些是当时版本的验收记录，复验请运行本文命令，不代表源站之后不会限制访问。

正式入口浏览器验收覆盖了粘贴整段抖音分享文案、识别单作品、点击一次「直接下载」、自动入队、完整 MP4 导出和自然播放至结束。成片 20.567 秒、H264 + AAC，导出哈希与服务器文件一致，全片解码通过，617 帧、零丢帧。另一独立访客没有该素材，跨空间详情、原件、缩略图与结果均返回 404。

曾发现 CDN 命中旧 JavaScript，因此公开 HTML / JS / CSS 设置 `Cache-Control: no-store`，并为实际入口模块更新版本查询参数。部署时应沿 HTML 中的实际模块 URL 核对内容、缓存头和浏览器加载结果；不能只以随意追加参数的一次请求作为验收。缓存指令见 [Cloudflare 官方文档](https://developers.cloudflare.com/cache/concepts/cache-control/)。

历史验收报告、媒体样本、实际域名、运行镜像和私人回滚记录不随源码发布。通用升级与配置步骤见 [部署说明](DEPLOYMENT.md)，重新验收可用 `scripts/social_acceptance.py` 生成自己的报告。
