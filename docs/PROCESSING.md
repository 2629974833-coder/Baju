# CPU 处理、原件与成品版本

本地入口：[处理工作台](http://127.0.0.1:4173/#process)。本阶段把原型中的手动处理接入真实文件和持久化队列，不增加 GPU 或超分。服务器安装与运行仍需后续现场验收。

## 操作流程

1. 在素材发现中下载文件，或从「文件与成品」选择已有原件进入处理台。
2. 工作室在「预览剧集」按剧名切换，左侧只列本剧已下载的视频，可按集选择或全选。未归集视频和其他素材各有入口；从资料库跨剧送入的勾选保留在临时批次。批选图片或视频，选择「加水印」「去水印」「去除后加水印」。每项从自己的原件生成独立版本，原件不覆盖。
3. 加水印可设置文字、四角位置、不透明度和字号占画面高度比例。固定水印可在画面上框选区域。单个视频的移动水印可选「随时间移动」，在暂停的画面中框住水印，记录位置，再移到下一个时刻记录新位置。平滑移动会在两个位置间插值，瞬间换位会在后一时刻切换。首个位置起生效，最后一个位置保持到片尾。尽量贴紧文字边缘，可减少对背景的影响。
   春楼视频还可直接点「一键去飘动水印」。有勾选时处理所选视频，没勾选时处理当前预览。默认生成「春楼飘字精修」，结合前后帧修复匹配的半透明字形。点击对应任务的「查看成品」可直接打开这一版。任务和成品详情均显示识别并修复的帧数，完全未识别到则保留原件且不登记成品。
4. 配置预览只展示位置，完成后的实际效果在版本预览中查看。处理队列显示进度和失败原因。可暂停、继续、重试或取消，也可点「删除任务」移除记录。对运行中的任务确认删除后，工作室会先停止处理并清理未完成的文件。已生成的成品仍可从资料库打开。
5. 在成品详情选择版本，查看原件与成品对比，单独保存原件或处理版本。资料库的视频按剧名折叠、按集序排列，可搜剧名或集号；未归集视频仍可找到。文件库可按来源、图片/视频、标签/名称及成品状态筛选；批量 ZIP 按来源与媒体类型归类，附文件哈希和缺项清单。

选区预览以浏览器实际解码尺寸为准，包含图片 EXIF 与视频显示方向；加载完成前不能拖框。视频对比是两个独立播放器，不宣称逐帧同步。正在播放、拖框或编辑时，后台轮询保留当前操作。

## 实际算法和输出

| 输入 / 动作 | 实现 | 输出与边界 |
| --- | --- | --- |
| 静态图片加字 | Pillow 字体渲染与透明度合成 | PNG，保留透明通道并规范化 EXIF 方向 |
| 静态图片固定区域去除 | 周边像素插值 | 使用矩形边缘估计内部，复杂背景可能留痕，不是 AI 恢复 |
| 视频加字 | Pillow 透明文字图层 + FFmpeg overlay | H.264/AAC MP4，CPU 重新编码 |
| 视频固定或移动区域去除 | FFmpeg delogo | 支持固定框，或按 1–32 个关键帧移动同一大小的框。复杂纹理可能变软。 |
| 春楼视频的一键飘字修复 | OpenCV 按背景亮度追踪字形，从相邻帧取回露出的背景纹理；H.264/AAC MP4 | CPU 处理，可接受最多 3840×2160 像素、不放大；低置信帧跳过。复杂细节可能留淡痕，修复帧数不代表画质评分。 |

动态图像不会被静默截成首帧，当前会明确拒绝。视频保留并核对音轨数量、语言、声道和可得时长；规范化显示方向，奇数宽高补到相邻偶数，不放大画面。处理版本不是原始封装的无损副本，原始封装、字幕或附件应保留在原件中。

当前为单个 CPU 处理任务，FFmpeg 使用有界线程；Pillow 图像/图层工作在可终止的本地子进程中。取消后先确认子进程退出，再清理本次临时输出。输入上限为 4000 万像素、6 小时视频，输出上限 2 GiB；处理有超时和磁盘余量检查。超限、缺字体、异常文件或音轨校验不一致都会失败，不标记成品已完成。

中文默认查找本机可用字体；Linux 容器安装 `fonts-noto-cjk`。原生环境可设置 `FRAMEKEEP_FONT_PATH=/absolute/path/to/font.ttf`。字体必须覆盖输入文字，否则明确失败，不静默生成缺字方框。路径是管理员启动配置，处理接口不接受任意字体文件路径。

## 队列、保存与恢复

处理任务独立保存在 `processingJobs`，不混入下载队列。运行任务在服务重启后变为暂停；继续时从原件重新处理，不提供编码帧断点续算。暂停、取消或失败只清理本次未登记输出，原件及已经完成的版本保留。

相同素材与规范化参数的活动任务或有效已完成成品会去重，重试历史失败任务也遵守此规则。不同参数产生新的版本 ID。文件先写入版本临时目录，验证尺寸、时长、音轨和 SHA256，复核原件在处理期间没有变化，再原子保存并登记版本；只有完成版本才有可预览/导出的文件地址。

成品归档使用来源、媒体类型及已有素材标签/分类，不是语义 AI 自动识别。自动触发处理、定时规则、更多站点接入仍属于阶段四；本阶段从面板手动提交真实任务。

## API

- `POST /api/processes`：`{ids,options}`。
- `options`：`mode` 为 `add/remove/both`，`text` 最多 80 字符，`position` 为四角字符串，`opacity` 为 0–100，`fontSize` 为画面高度的 1–20%；`region` 的 `x/y/width/height` 均为百分比。去除模式不要求文字，加字模式不允许空文字。
- 工作室一键春楼精修提交 `{"mode":"remove","method":"chunlou-glyph","revision":2}`，省略 `revision` 的旧请求使用原版算法，仅接收已保存的春楼视频，可批量。成品记录 `glyphFrames` 和 `totalFrames`。
- `POST /api/processes/{id}/action`：`{action:pause|resume|retry|cancel|delete}`。
- `GET /api/assets/{id}/versions/{versionId}/file`：支持媒体 Range，`?download=true` 下载；`original` 指向原件。
- `POST /api/library/archive`：`{ids,variant:latest|original}`。`latest` 只打包各项最新已完成成品，没有成品的条目列入清单，不伪装成原件替代。

文件位于 `assets/<asset-id>/versions/<version-id>/processed.png|mp4`；对外状态不暴露私有文件路径。版本保存参数、处理器、方法、源/输出 SHA256 和元数据，完整工作区备份一并包含这些文件和记录，见 [运行维护说明](OPERATIONS.md)。

## 本地验收与复跑

```sh
uv run pytest tests_backend/test_processing.py tests_backend/test_processing_queue.py tests_backend/test_processing_api.py tests_backend/test_chunlou_glyph.py -q
uv run python scripts/processing_acceptance.py
uv run python scripts/processing_acceptance.py --serve --port 4198
```

自动验收生成两份中性原件，实际执行图片/视频三种模式，检查六个核心版本的字节、像素变化、视频完整音视频解码、双音轨与时长、Range、分类 ZIP 和去重；另外验证暂停及服务重开后的重新处理，再做在线备份→校验→CLI 新目录恢复→全部文件哈希核对。报告 `test-output/stage23-processing-acceptance.json`。

`--serve` 提供隔离的 [4198 处理面板](http://127.0.0.1:4198/#process)，只放入本地生成的图片/视频用于操作验收，不使用主工作区账号或媒体；退出后清理一次性数据。验收只说明这些受控样例的效果与流程，不代表任意水印都能无痕去除。

春楼初版实片验收（本机）：在工作室选《想要和你一起》，勾选第 1、2 集后提交一次。两集均产生独立 MP4，原件哈希不变；第 1 集识别并修复 936/988 帧，第 2 集 2923/3145 帧，均通过全片音视频解码与 Chrome 成品播放至片尾。再次提交返回两项重复，不产生第二份同参数成品。具体本机文件和计数见 `test-output/studio-series-glyph/results.json`。其他节目或字形需要单独验证。

精修版从两集原件重新生成。正式 MP4 的第 1 集 29.93 秒和第 2 集 37.57 秒均已复核。在可测的原始画面上，以残余字形强度超过原来的 68% 作为明显残留的比较阈值，第 1 集由 50 帧降至 4 帧，第 2 集由 204 帧降至 8 帧。完整播放验收和原速局部对比分别见 `test-output/glyph-v2/results.json` 和 `test-output/glyph-v2/两集-飘字原速对比.mp4`。
