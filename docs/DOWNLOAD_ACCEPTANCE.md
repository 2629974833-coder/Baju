**最终实站续传通过：暂停后保留 2 个完整片段，重启服务实例后复用 1,542,728 字节，32 个片段完整完成。** 源站实测忽略 If-None-Match 而返回 200，未声明 Content-Length，但返回相同强 ETag。下载器已兼容这一情况：仅完整缓存 SHA 校验通过、最终 URL 与强 ETag 相同，且 MIME、编码与声明长度检查通过时复用。该优化不用于半截缓存、弱 ETag、仅日期验证器、URL 变化或认证错误。完整记录见 `live-lustflix.json`，源站行为诊断见 `lustflix-conditional-diagnostic.json`。

## 实际支持边界

- HTTP 续传依赖可验证的远端文件身份和正确 Range 响应。弱 ETag 不作为 If-Range 依据；日期验证器必须满足强验证条件。完整片段复用也要确认远端资源未变化。
- 检查点每累计约 4 MiB 及暂停/网络中断时写入，原子替换并同步落盘。恢复先验证前缀哈希；进程异常退出后，检查点之后的未确认尾部不会被盲目拼接。
- 瞬态网络故障以及 408 / 429 / 5xx 每资源最多尝试 4 次；单次等待最多 5 秒。401 / 403、登录 HTML、无效媒体、格式不支持不会无限重试。暂停和取消可中断等待。
- 默认单任务 2 GiB，可通过部署配置调整。HLS 点播继续支持普通 AES-128 与独立音轨；静态单 Period DASH 已在后续开源接入轮次支持（见 [开源接入](OPEN_SOURCE_DOWNLOADS.md)）；DRM、直播、HLS 字节范围及部分扩展仍不支持。
- 自动“正片候选”是内容类型推断，不等于通过源站权限验证或整集完整性证明。Lustflix 根据单集播放路由及媒体集号识别；通用网站优先使用媒体自身路径和播放器标签。单靠页面标题或视频长度不会认定正片。
- 此次批量传输夹具是 PNG；60 分钟夹具刻意使用低分辨率、低码率。测试分别证明队列隔离、时长处理与流式字节量，不代表持续多日负载、任意高码率编码或四个目标站点已全部适配。
- 进程崩溃验收覆盖真实 SIGKILL 与新解释器恢复，不模拟断电或存储设备损坏。RSS 是高水位指标；外部媒体工具的内存单独记录，不混称整机内存占用。

## 可复用验收命令

```sh
uv run pytest tests_backend -q
uv run ruff check backend tests_backend scripts/download_acceptance.py
npm test
npm run check
uv run python scripts/download_acceptance.py
git diff --check
```

长媒体脚本仅使用本地受控 HTTP 服务，不连接真实账号；结束清理临时媒体，保留 `test-output/download-reliability-20261103/controlled-media.json`。报告含源码 SHA、字节量、轨道、全量解码、Range、RSS、磁盘峰值和测量限制。`baseline-controlled-media.json` 保留旧实现重传完整文件的失败证据。`tests_backend/test_download_resume.py` 与 `test_download_queue.py` 是故障及批量复跑入口。

## 日常恢复流程

1. 在下载队列暂停任务；继续时查看“复用字节 / 片段”及源站续传提示。
2. 网络失败可直接重试，系统重新校验保留数据。登录失效或链接过期先在站点窗口检查权限并重新扫描。
3. 服务重启后，检查暂停任务并继续；queued 自动等待调度。不要启动第二个服务写同一数据目录。
4. 取消会清理临时下载，保留已验证原件。迁移或备份需同时保留 SQLite、会话密钥/加密状态、原件及私有检查点。

协议依据：[HTTP validators / range](https://www.rfc-editor.org/rfc/rfc9110.html)、[HLS](https://www.rfc-editor.org/rfc/rfc8216.html)。部署变量、磁盘与备份说明见 [DEPLOYMENT.md](DEPLOYMENT.md)。
