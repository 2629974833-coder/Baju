# 剧集库：单链接扫描与批量保存

本地入口：`http://127.0.0.1:4173/#series`。

**整站归档：** 在总览粘贴站点主页或剧目索引，选择「整站」。结果会直接归入这里，与单独添加的同一部剧合并。按来源分组，支持分类、剧名与编号筛选，每页 12 部；分类以站点提供的信息为准。未读取完的目录可从站点进度卡点「继续拾取」。

**直接下载一部剧：** 点剧卡上的「下载本剧」，后台会读取尚未解析的目录、扫描检查可访问的单集，再自动加入视频和海报下载任务。关闭页面不影响后台任务；重复提交会复用已有文件或队列项。这个快捷入口不执行金币购买。需要选择画质、语言或只下载几集时，展开单集目录后沿用选集下载。

**海报与 ZIP：** 剧卡显示海报下载状态。保存完成后点「导出本剧（含海报）」，ZIP 直接包含剧名文件夹、视频、海报及清单；海报排队时显示「等待海报保存」。没有可用海报或海报下载失败时，可导出已有内容并在清单中查看缺失，不会把海报当作单集视频导出。

**Lustflix 示例：** 在「添加剧集」粘贴 `https://lustflix.tv/#/watch/C13/1`，点「扫描整部剧」。也可以直接粘贴详情链接（如 `https://lustflix.tv/#/s/C37`）或带集号的分享链接（如 `https://lustflix.tv/#/s/C04/1`）。面板先读取该剧公开发布的选集目录，用站点给出的实际集号列出条目；不需要再输入其他集的链接。这一步不访问每集播放器、不下载，也不解锁。目录条目不代表已获得播放权限或已有可下载文件；展开单集目录后可点「扫描并检查全剧」，或勾选需要的集数后点「扫描并检查所选集」。

**春楼示例：** 展开「单集目录」后，勾选一集即可查看最近一次扫描的具体结果。「权限待核实」表示公开目录有标价，是否已购还未确认；点「扫描并检查所选集」会使用当前站点会话复查。「暂不支持此播放格式」表示已找到播放器，但没有可供拾帧导出的正片，重复扫描或登录不会改变视频格式。

**自定义名字：** 可以在添加时填「自定义剧名（选填）」，也可以点已有剧集卡的「改名」→「保存剧名」。清空并保存会恢复站点剧名（站点未给出时用编号）。自定义名用于目录展示，仍可用原剧名或编号检索；重新读取目录不会覆盖已设置的名字。

1. 粘贴一个有明确选集列表或结构化剧集目录的详情页、播放页，点击「扫描整部剧」。默认本轮最多读取 100 页，可设为 1–1000 页。
2. 在单集目录点「全选当前结果」，再点「扫描并检查所选集」。只处理几集时直接勾选它们。没有勾选时，这个按钮会检查全剧；设置了筛选时会显示并检查当前结果的数量。
3. 面板显示已检查的集数和总进度。当前会话可播放且能识别正片的集会标为可下载，有购买门槛的集显示需要权限。可取消扫描，触发限流等中断时可查看已完成和未检查的数量。
4. 点击「下载本剧可用集」或勾选单集后下载，设置源站画质和语言。目录和处理结果保存在本机。
5. 在站点登录或手动解锁并保存会话后，可选中相应集数，再点同一个检查按钮更新结果。

**只导出一集：** 在剧集卡展开「单集目录」，只勾选一个标为「已保存」的单集，点击「导出第 N 集原件」。浏览器会直接保存该集的原文件，文件名包含剧名和集号；「导出全部已保存集（ZIP）」会生成 `剧名.zip`，解压后视频和 `manifest.json` 就在剧名文件夹里。设置过自定义剧名时使用自定义名。未保存的集数不能导出。

## 扫描时用账号金币解锁

在 Lustflix 或春楼的「单集目录」勾选「本剧自动用金币解锁」，选择要检查的集数，再点「扫描并自动解锁所选集」。按钮会显示本次范围。没有勾选单集时，范围是当前筛选结果，未筛选时是整部剧。首次默认关闭，浏览器会记住每部剧的开关和预算。每次提交重新计算本批预算，留空时使用站点账号可用金币。

免费、可播放或已有权限的集直接扫描。对于站点明确标价的锁定集，拾帧在下单前重新核对账号、单价、余额和剩余预算，逐集提交。余额或预算不足会跳过该集，后续较便宜的集仍可处理。确认购买后会再检查该集的正片，批次显示确认解锁数、实际扣币和待核对结果。

春楼下单时一并提交预期单价，站点改价会拒单。Lustflix 按下单前的报价核对预算，其接口不支持锁价。如果站点在结算瞬间涨价，拾帧会显示实际支出并停止本批后续付款。Lustflix 账号有可用单集券时，站点可能优先用券，拾帧会跳过这些付费集。

付款结果不明确时，拾帧保留该集订单并暂停本批后续扣币。可到站点账单核对，再点扫描检查权益。重复扫描或服务重启后，拾帧不会自动重付这笔未确认订单。

## 扫描提示与切换代理

详情页、分享页和播放链接均可用公开目录列集。DNS 暂时不可用、连接中断或网关暂时不可用时，扫描器会有限次重试。客户端切换出口后，连接旧 IP 失败会重新解析并检查地址。只读策略拦住页面的写请求并不等于账号失效；若站点明确要求登录、授权或真人验证，仍需在「站点与授权」处理。

在剧集库点「清除提示」，或「清除当前提示（N）」后确认。刷新面板不会再显示已清除的提示；历史记录、剧集、任务和原件都保留。新的扫描如果失败，会显示新的提示。「填写链接重试」只回填原链接，由你决定是否再次扫描。

## 筛选与移除

在剧集页按剧名、编号、来源或分类筛选，勾选整部剧后点「移除所选整剧」。「全选本页」只选择当前页的剧，换页可继续勾选。要清理某几集，先展开这部剧的「单集目录」，按集号、标题或状态筛选，再勾选并点「移除所选单集」。「全选当前结果」只选当前筛选可见的单集，确认框会列出本次操作的范围。

移除只整理目录，不删除已保存文件、下载任务或扫描历史。刷新、重启或移除前已经运行的扫描都不会自行恢复整剧。要重新加入，可在总览重新拾取整站，或在「剧集 → 添加剧集」粘贴原详情页、同剧单集链接并重新扫描。扫描成功识别为同一部剧后，会恢复原来的卡片和自定义剧名；此前单独移除的集数仍隐藏。失败或取消时保持移除状态，可以重试。从「总览 → 扫描历史」可重开已保存的扫描结果。

## 识别范围

通用目录识别目前支持明确标注 `aria-label="Episodes"`、`Episode list`、`剧集`、`选集` 或 `劇集` 的可见目录，以及目录内实际链接上的 `data-episode-number`、`data-ordinal`、`Episode N`、`第 N 集`。支持此目录范围内的滚动、加载更多/下一页按钮，以及播放页上的显式 `rel="up"` 目录链接。`data-series-url` 可提供稳定目录身份；同一轮及后续续扫沿用该身份。

结构化目录支持页面已有 JSON-LD 中的 [TVSeries](https://schema.org/TVSeries)、[TVSeason](https://schema.org/TVSeason)、[TVEpisode](https://schema.org/TVEpisode)，以及属于明确剧/季的 [ItemList](https://schema.org/ItemList)。要求实际同源播放页 URL 和明确 `episodeNumber`，不把列表位置当作集号；总集数只采用明确声明。支持本页 `@graph` / `@id` 引用、播放页到明确父目录的跟随，不联网读取 `@context`。这是受约束的字段解析，不是完整 JSON-LD 处理器。

同一页的可见目录与结构化数据必须在目录身份、集号和播放地址上相符；冲突时暂停自动展开，跨季内容不会混为一季，普通推荐及面包屑不作为剧集目录。结构化数据每页限 32 个脚本、合计 512 KiB、5000 个对象/数组节点、32 层深度、16 层引用和 10000 次关系遍历；共享引用去重，超限时不采用部分结构化目录，独立有效的可见目录仍可工作。目录卡片显示「页面选集」「结构化数据」等实际来源。

没有共同目录身份的独立播放页可能归为不同系列。暂不支持任意网站布局、只有脚本点击行为的未知选集控件；不猜测 URL 或总集数。其他未知站点仍依赖上述目录证据；Lustflix 播放链接可使用开头所述的公开剧集目录。

通用正片候选必须来自已发现目录中的精确页面，且播放器明确处于主内容区域；证据绑定页面和媒体地址。预览及独立音轨优先排除；多个不同主媒体保留为待确认。目录总数来自页面明确声明，未知总数、缺号、重复编号冲突、权限项均不标作完整。

Lustflix 列目录仅发送匿名读取请求。网页扫描使用独立会话副本并限制写入请求。主动开启金币解锁时，逐集购买由对应站点的支付接口执行。浏览器每轮还有 300 秒、素材容量和目录遍历上限；耗时较长时保留已发现结果并继续扫描。

## API 与数据

- `GET /api/state` 的 `series` 是从现有扫描和素材派生的视图，没有另一套目录数据库。
- `POST /api/series`：`{url, siteId?, limit?, customTitle?}`。显式提交已移除整剧的链接时，受理后仍须等待扫描成功；确认恢复时，该扫描记录的 `restoredSeriesId` 指向原来的剧集。
- `PUT /api/series/{id}/title`：`{title:"我的剧名"}`；传空字符串恢复来源名称。
- `POST /api/series/dismiss`：`{ids: [seriesId, ...]}` 移除整剧；`{ids: [seriesId], episodeKeys: [...]}` 只移除指定单集。响应中的 `dismissed` 是本次新移除的数量。
- `POST /api/scans/{id}/discovery-dismiss`：`{scope:"catalog"}` 隐藏这次扫描在发现页的目录，或用 `{scope:"episodes", episodeKeys:[...]}` 隐藏指定集。只接受这次扫描实际记录的集；重复操作不会扩大范围。
- `POST /api/scans/discovery-dismiss-group`：`{scanIds:[...]}` 只清理列入确认范围的同剧扫描目录，不按标题匹配。整批校验通过才写入；重试不会清理新扫描。
- `POST /api/series/{id}/scan` 接受 `{episodeKeys:[...], scanAndCheck:true}`。一次提交最多 1000 个本剧已观察到的集号，任务用 `checkedCount/checkTotal` 报告进度。旧调用仍可用 `limit` 和 `recheckAccess` 分开执行扫描或复查。
- 金币解锁仅适用于 `GET /api/state` 的 `coinUnlockSiteIds` 已列出的来源。向同一检查请求额外传入 `autoUnlock: {maxCoins: 20}` 可按本批预算购买；传 `autoUnlock: {}` 按可用余额购买。必须显式传选集。扫描记录的 `unlockSummary` 和 `unlockResults` 分别给出本批统计和逐集结果。
- `POST /api/intake`：整站传 `{scope:"site", url, catalogOnly:true}`，只列剧和读取目录；旧调用默认仍可继续解析单集。续扫继承此选项。
- `POST /api/series/{id}/downloads`：`{episodeKeys?, options?, resolveMissing?}`；默认沿用原选集行为，并补齐本剧海报。传 `resolveMissing:true` 时后台先扫描检查未解析单集或目录，然后入队；响应可包含 `resolving:true`、`scanId`，完成结果在扫描的 `downloadSummary`。
- `POST /api/series/scan-notices/dismiss`：`{scanIds:[...]}`，隐藏指定的已结束扫描提示。
- `GET /api/series/{id}/episode-file?episodeKey=…`：导出单集已保存原件，支持 Range。
- `GET /api/series/{id}/archive`：导出已保存主媒体和海报，保留原件存储位置。清单分别记录单集和海报，海报不计入已保存集数。

权限变化只依据本轮实际访问精确页面的结果；历史素材不会替代新的访问证据。原 `/api/scans` 接口继续可用。

已标记「需权限」的条目不会因目录重新出现或旧素材存在而自动放开。批量权限复查只有在精确页面新观察到有效主视频证据时才清除旧限制；仍拒绝、空页面、隐藏视频、旁栏或仅文件名包含 episode 的请求均不会清除限制。私有复查历史只记录实际尝试页面，用于分批排序，不能代表访问成功。
