# 本地运行维护、完整备份与恢复

本阶段先在本机完成运行维护功能；真实服务器的镜像构建、网络入口、磁盘卷权限和长时间运行，由后续服务器实测单独确认。本文中的短时故障注入不能代替服务器连续运行验收。

## 运行状态

面板「设置」中的运行维护区域读取 `GET /api/operations`。`GET /api/ready` 使用同一诊断结果，就绪时返回 200，否则返回 503；原 `/api/health` 保留进程存活检查。部署监测应同时区分存活和就绪。

诊断包括运行时间、数据库读取状态、磁盘总量/已用/剩余/保留空间、FFmpeg/FFprobe/Pillow/Chromium 安装发现、下载、处理与自动化工作循环、队列数量和最近失败的任务编号。依赖安装发现只在启动时执行并缓存，不会打开账号或访问源站；实际媒体处理和浏览器可用性仍需相应功能验收。

下载、处理和自动化调度分别更新心跳。循环已经退出、超过 15 秒没有心跳、数据库读取异常、必需依赖未发现或磁盘低于阈值，均使就绪状态下降。最近失败只输出编号、类型、状态、受控原因码及时间，不输出源地址、Cookie、授权头或原始异常内容。

`FRAMEKEEP_MIN_FREE_BYTES` 设置磁盘保留阈值，默认 `536870912`（512 MiB）。下载、CPU 处理和备份共享空间检查，开始前及写入期间重新检查实际可用量；空间不足时保留已验证原件，停止当前写入，并显示可处理的空间错误。释放空间后再继续或重试。它是程序的写入保护，不是操作系统磁盘配额；其他进程仍可能消耗同一磁盘。

每个工作区只允许一个服务进程。程序在 `.workspace.lock` 上持有操作系统文件锁；即使使用不同端口，第二个进程也不能同时使用同一数据目录。进程正常退出或被操作系统终止后，锁自动释放。锁文件保留属于正常现象，不能靠删除锁文件来处理占用；应先停止实际持锁进程。

## 面板创建和校验备份

1. 暂停下载和处理，完成或取消扫描，等待活动操作退出。
2. 在运行维护区域点击创建备份。后端会拒绝仍有排队/运行任务或其他写操作的情况。
3. 备份期间进入维护状态，停止接收新的写入；已打开的站点会话先保存，再复制快照。页面读取和已有文件读取仍可用，可能写入缓存的操作受维护限制。
4. 成功后显示文件数量、总字节和本次校验结果。普通列表显示「未复查」，不把以前的成功结果当成当前完整性证明；可再次点校验，对全部文件重新计算哈希。

对应 API：

- `GET /api/maintenance/backups`：只列出有完整有效清单的备份元数据，不在轮询时读取所有媒体文件。
- `POST /api/maintenance/backups`，正文 `{}`：创建一致快照。
- `POST /api/maintenance/backups/{id}/verify`，正文 `{}`：重新读取所有文件、核对大小与 SHA256、数据库引用及会话密钥配对。

备份位于工作区 `backups/backup_<id>/`。它包含 SQLite 一致快照、原件、处理版本、缩略图、未完成下载的片段/检查点、加密会话和对应密钥。`backups` 本身不会递归纳入后续快照。目录 0700，文件 0600；清单也属于私有资料。备份携带恢复账号状态所需资料，只应保存在个人受控存储中。

创建前检查目标磁盘的预计空间，复制以 1 MiB 块检查剩余空间，SQLite 备份按有界页批次检查。空间不足或文件在复制期间变化时，不发布成功快照；只清理本次临时数据，保留原工作区。备份默认保存在同一磁盘，服务器上线后还需要复制到另一受控位置，才能覆盖整盘损坏的情况。

## 离线 CLI

CLI 使用与服务相同的工作区锁。创建备份前先停止服务；不要尝试用第二个进程绕过正在运行的服务。

```sh
uv run python -m backend.backup create \
  --data-dir .framekeep \
  --output ./private-backups/framekeep-before-upgrade

uv run python -m backend.backup verify \
  --backup ./private-backups/framekeep-before-upgrade

uv run python -m backend.backup restore \
  --backup ./private-backups/framekeep-before-upgrade \
  --data-dir ./framekeep-restored
```

`create` 必须使用尚不存在的输出目录。工作区内只允许 `backups/` 下的新快照，工作区外可以指定独立备份磁盘。`create` 和 `restore` 可用 `--min-free-bytes` 覆盖保留量，否则读取 `FRAMEKEEP_MIN_FREE_BYTES` 或使用 512 MiB。

恢复目标必须不存在或为空，且位于备份与原工作区之外。程序首先完整验证备份，然后在目标旁建立私有临时目录，持锁复制并再次核对文件，最后通过同一文件系统的原子目录重命名发布。发现损坏、缺失、路径穿越、符号链接、会话密钥不匹配或空间不足时拒绝恢复；不会覆盖用户已有目录或把半份数据库交给服务。

恢复命令不会启动下载或处理任务。确认返回 `restored: true` 后，可用新目录启动本地服务：

```sh
FRAMEKEEP_DATA_DIR=./framekeep-restored FRAMEKEEP_PORT=4174 uv run python -m backend
```

首次启动会将中断中的下载与处理改为暂停，扫描改为中断失败。下载继续时仍要验证检查点；CPU 图像/视频处理继续时从原件重新处理。尚未开始的排队任务会按现有队列规则运行。启用中的自动化规则会按数据库内保存的下次执行时间恢复检查；请在隔离网络中演练有启用规则的生产备份。先在隔离端口检查记录、原件、处理版本和会话，再决定服务器的正式切换。

当前备份格式版本为 1，接受单工作区 SQLite 数据格式版本 1。清单上限 32 MiB、文件数上限 100000；不接受符号链接或特殊文件。恢复只写入普通目录，不解压归档，也不执行备份中的脚本。

## 本地验收与服务器交接

```sh
uv run pytest tests_backend/test_operations.py tests_backend/test_backup.py -q
uv run python scripts/operations_acceptance.py --seconds 180
```

专项脚本使用一次性工作区和合成 PNG/版本/空浏览器会话：验证真正的 CLI 往返、持锁子进程被强制终止后释放锁、真实 API 健康采样、在线备份与显式复查、低磁盘与调度循环退出时 503、重新启动后恢复就绪，以及下载/处理/扫描的中断状态。退出后删除一次性数据，只保留 `test-output/operations-acceptance.json`。

`--seconds` 可以设为 3600 等更长时间；报告记录实际时长与采样次数。短时本地通过不能推导全天稳定或特定服务器已经通过。服务器实测还需检查容器启动/停止、反向代理或 SSH 隧道、实际挂载卷空间与权限、远程备份副本及从副本恢复、目标负载下的连续运行和断电/重启恢复；部署参数见 [DEPLOYMENT.md](DEPLOYMENT.md)。
