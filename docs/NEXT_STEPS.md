## 1. 后端与持久化

建立 FastAPI、数据库和文件存储。将浏览器中的站点、素材、任务、规则和版本数据迁入持久化模型，定义 API、任务状态和失败原因。

原始文件、缩略图和处理结果分别存储；保留素材来源与处理参数。先使用服务器磁盘，容量和多机需求明确后再接对象存储。验收重启恢复、状态一致性和文件关联，不以页面中的模拟进度作为完成证据。

## 2. 真实站点会话与授权

按用户和站点隔离登录会话。站点支持 OAuth 时使用其正式流程；其他站点可提供远程浏览器，由用户完成登录和必要的交互，再记录有效期与访问权限。

不假设所有站点都能嵌入 iframe。面板需要展示连接状态、会话过期、退出和重新授权入口；敏感会话资料保存在受控后端，不放入浏览器演示数据或日志。

付费剧集先读取真实订单信息，展示具体内容、价格和账号。只有用户明确确认具体订单后，才进入对应站点的实际支付流程；会员权限也不能直接视为已解锁全部内容。原型的「确认模拟解锁」不产生付款或任何远端授权。

## 3. 扫描与站点适配

选择少量实际目标站点，接入 Crawlee / Playwright，并优先使用可用的正式接口。分别处理目录遍历、分页、懒加载、素材元数据和访问范围。

扫描需有页面数、深度、速度和停止条件。先生成候选清单，再由用户挑选。验收已知目录的发现完整率、重复率及权限边界；无法访问或枚举的范围必须明确显示，不能用「扫描结束」代表「全站全部发现」。

## 4. 下载队列

接入直接 HTTP 下载、yt-dlp 和 gallery-dl，并根据站点与媒体类型选择处理器。使用持久化任务队列执行下载，支持取消、失败重试、进度报告、去重及可用时的断点续传。

先验证下载文件的实际可播放性、时长和完整性，再标记完成。会话过期、链接过期、权限不足和格式不支持应有不同的恢复入口；增加组件不代表任意站点都会受支持。

## 5. CPU 水印处理

已接入 Pillow 图片水印与边缘插值、FFmpeg 视频水印与 delogo，处理区域由用户在真实画面上选择或填写百分比。三种模式均产生实际输出并记录参数，操作流程见 [PROCESSING.md](PROCESSING.md)。图片 AI 修复、移动水印跟踪与复杂背景修复未在本阶段启用。

视频像素处理通常需要重新编码，应测量 CPU 占用、处理时间和输出体积。移动水印或复杂背景的修复单独评估，不承诺无痕恢复。保存原件、输出版本、参数和失败原因，并提供处理前后检查。无超分辨率阶段。

## 6. 真实成品归档与持续运行

实际成品已接入文件库，提供原件/版本预览、来源和媒体类型筛选、标签/名称搜索及文件/分类 ZIP 导出。已完成的版本才有可访问文件地址，原件保持不变。运行维护与完整备份恢复的本地实现和故障注入见 [OPERATIONS.md](OPERATIONS.md)，服务器持续运行仍待现场验收。

第四阶段已为指定页面接入后台规则调度；单页增量扫描、去重及恢复见[自动化使用说明](AUTOMATION.md)。评估存储增长、带宽与 CPU 成本后，逐步增加并发和站点数量。

## 验收与排查入口

- 原型回归：`npm test`、`npm run check`、`npm run dev:demo`。
- 真实后端：`uv run pytest tests_backend -q`、`uv run ruff check backend tests_backend`、`npm run dev`。
- 第二、三阶段：`uv run python scripts/operations_acceptance.py --seconds 180`、`uv run python scripts/processing_acceptance.py`。
- 业务回归：授权 → 扫描 → 选择 → 下载 → 处理 → 成品；原件必须保留。
- 真实站点验收：记录目标范围、发现数量、可访问数量、下载成功率、失败原因、处理耗时及抽查结果。
- 故障排查：从任务 ID 关联站点、素材、执行日志和输出文件；确认权限与链接有效性后再重试。
- 发布边界：前端静态原型发布成功，只证明原型可访问；真实登录、支付、抓取和处理能力分别验收。
